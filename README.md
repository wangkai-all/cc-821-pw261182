# 再保条款顺序与额度恢复实验室

一个零运行时依赖的静态网页 + 可测试结算引擎，用**虚构损失事件**逐笔演示：

- 每次事故免赔、单层/多层起赔点、单次限额、年度限额；
- 有限次数的额度恢复、恢复费用和生效等待限制；
- 同一事件的迟到补损、估损冲回回到原事件，不重复计算免赔；
- 多层按明确条款顺序结算，杜绝各层独立计算后赔款之和超过原损失；
- 事件顺序 A/B 重放、剩余额度前后对比、分摊尾差追踪；
- 不可变结算版本与 JSON 导出；
- 跨年度、限额耗尽、恢复失败、生效等待和尾差样例。

> ⚠️ 所有公司、事件、日期和金额均为虚构。本项目只用于条款逻辑与工程演示，不作真实保险/再保险建议。

## 内置样例

1. `order-effect`：两笔损失合计 ¥740，顺序不同导致自留相差 ¥100。
2. `development`：`+250 → +120 补损 → −70 冲回`，免赔 ¥100 只用一次。
3. `cross-year`：2025 事件在 2026 年补损，仍适用 2025 合同；2026 事件额度独立。
4. `exhaustion-failure`：初始额度 + 两次恢复用尽后，第三次恢复因次数上限失败。
5. `reinstatement-wait`：恢复需经过一笔后续流水，紧邻事件无法使用。
6. `rounding-tail`：¥100.01 在 33.33%/33.33%/33.34% 共保人之间分配，一分尾差可追踪。

## 核心守恒关系

每笔流水：

```text
免赔行 + 各层摊回行 + 限额缺口行 + 未分配留行 = 该笔有符号增量
```

每次结算总计：

```text
自留合计（免赔 + 限额缺口 + 未分配）+ 各层摊回合计 = 原始损失合计
```

测试会对所有样例的 A/B 顺序逐笔验证上述等式。

## 版本化结算

网页中的当前 workbook 是可编辑草稿。每次点击“应用条款并重算”“加入流水并重算”或“交换顺序并重算”，都会：

1. 深拷贝当前 workbook；
2. 分别结算 `orderA` 和 `orderB`；
3. 生成新的不可变版本 `vN`；
4. 保留所有旧版本及其 JSON 导出。

## 重要示范条款口径

- 恢复额度在“一笔正数支付把有效年度余额从正打到零”时申请，避免同一耗尽状态重复触发。
- `waitEntries = k` 表示恢复在同一合同第 `grantContractSeq + k + 1` 笔流水开始前生效；等待笔数按合同隔离，跨年度合同不互相计数。
- 恢复批单生成时即记录费用；样例中即使年末没有后续事件使用恢复额度，示范条款仍收取费用。可通过把费用率设为 `0` 或调整业务规则改变这一口径。
- 估损冲回按原多层路径回吐实际赔款，并减少年度已用净额；已消耗的恢复次数不自动返还。
